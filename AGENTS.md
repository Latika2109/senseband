## 1. Set up the whole project (laptop, no hardware needed)
Prerequisites: git, make, [uv](https://docs.astral.sh/uv/), Node 20+ (only for the app and cloud tests).
```bash
git clone https://github.com/Latika2109/senseband.git && cd senseband
make setup                         # .venv with Python 3.11 + all Python deps
(cd app && npm install)            # PWA
(cd cloud && npm install)          # cloud tests (PGlite = real Postgres in-process)
make test                          # ruff + all Python tests (edge + ml)  ~5 min incl. slow tests
(cd app && npm test && npx tsc --noEmit && npx eslint src)
(cd cloud && npm test)
```
Run it:
```bash
(cd app && npm run build)          # the edge service serves app/dist
make sim SCENARIO=fall             # http://localhost:8080  (scenarios: make sim-list)
make app                           # optional hot-reload UI on :5173 (proxies to :8080)
make train                         # optional: downloads ~1 GB datasets, retrains M1-M5 -> ml/models/
```
Real hardware: follow `docs/RUN_ON_HARDWARE.md` (never tested on a device; firmware never compiled).

## 4. Rules that must not be broken
- **Safety wording:** never diagnose ("possible irregular rhythm - share with your doctor", not "you have AF"). Keep the disclaimer.
- **Signal quality gating:** never raise a vital-sign alert from a poor signal (lead-off, finger-off, noisy, motion): raise "check sensor" instead.
- **Critical alerts** always go by SMS after the 30 s "I'm OK" window. Exercise: respect the doctor's maximum angle; pain >= 7/10 stops a session; plans are defaults a doctor/physio approves.
- **Never auto-delete patient data.** Export and erase must keep working (India DPDP Act 2023).
- **Offline-first:** the edge must keep working with no cloud, no internet, no BLE, any single sensor missing. Models have rule-based fallbacks.
- **One feature implementation** (`ml/senseband_features`); never copy it. Thresholds/paths/pins/phones come from config, never hard-coded.
- **Pi 3 budget:** edge RAM < 400 MB, models < 5 MB, inference < 50 ms. ONNX Runtime only on the edge (no PyTorch/TensorFlow).
- Python 3.11 + type hints + `ruff`; TypeScript strict + ESLint; add or update tests with every change.

## 5. How to test (and traps)
- Python: `make test`, or one file: `SENSEBAND_SIM=1 .venv/bin/python -m pytest edge/tests/test_rehab.py -q`. `addopts` already has `-q` (adding another hides the summary line).
- `edge/tests/harness.py::run_scenario(name, seconds, settings=..., on_frame=...)` runs a scenario through the real engine on a **data clock** (fast, deterministic). `make_settings()` disables the ML models; use `make_settings(models={"enabled": True})` to test them.
- Slow tests are marked `slow`; the full run takes minutes. The edge API tests start the real service in-process.
- When pasting commands from docs on macOS zsh, quote globs (`rm -f "dir/file"*`): an unmatched glob aborts the whole `&&` chain silently.
- Datasets in `ml/data/` are untrusted downloads: only the code in `ml/senseband_train/datasets.py` reads them (guarded extraction).

## 6. Conventions
Ids are UUID strings created on the band; times are UTC epoch ms; the band's patient id is generated once (`p-<12 hex>`) and is the cloud key.
Cloud is authoritative for profile/plans/limits/notes (`cloud_edited`); the band is authoritative for measurements (idempotent upserts).
Alert objects expose `raised_t` (never `t`: that is the WebSocket message type).

## 7. Definition of done for any change

3. Anything user-visible has English **and** Hindi text. 4. `CHANGELOG.md` line for notable changes. 5. A short, honest summary to the user.

## 8. What is NOT verified (don't claim otherwise)
Pi drivers, BLE link, SIM800L, GPIO, buzzer/button and the ESP32 firmware have **never run on hardware** (firmware never compiled).
Supabase Auth/Realtime/Storage, web push and SMS providers were not run on a live project. The band's local API has **no authentication**.
Model quality: M3 meets its target; M1 (0.85 vs 0.90), M4 (AF F1 0.74 vs 0.80), M5 (MAE 10.1 vs 8 bpm) do not; M2 (fall) was trained on
**simulated** falls only and is disabled. No accuracy on real people has been measured (`docs/07_VALIDATION_PROTOCOL.md` is the plan).
